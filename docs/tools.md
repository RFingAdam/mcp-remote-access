# Tools

`mcp-remote-access` exposes 26 MCP tools. Tools are registered under
the `remote-access` namespace when the server is loaded by an MCP
client. This page is generated by hand from the `Tool(...)` schemas in
[`src/mcp_remote_access/server.py`](https://github.com/RFingAdam/mcp-remote-access/blob/main/src/mcp_remote_access/server.py) —
if you're adding a tool, update both.

Most tools return a single formatted text block (e.g. `ssh_execute`
returns one string containing the exit code and stdout/stderr
sections, not separate typed fields) — this page describes what's *in*
that text, not a JSON shape, except where a tool explicitly returns
JSON (`serial_send_bytes`, `serial_read_bytes`).

## `ssh_connect`

Connect to a remote host via SSH.

**Arguments**

| Name           | Type   | Default | Description                                          |
| -------------- | ------ | ------- | ---------------------------------------------------- |
| `host`         | string | —       | Hostname or IP                                       |
| `username`     | string | —       | Login user                                           |
| `password`     | string | `null`  | Password (in-memory only). Pass `""` explicitly for empty-password auth — omitting the field entirely is treated differently from passing an empty string. |
| `key_path`     | string | `null`  | Path to private key                                  |
| `port`         | int    | `22`    | SSH port                                             |

**Returns** `connection_id` — always `"{username}@{host}:{port}"`, not
separately settable.

## `ssh_execute`

Run a shell command on a connected host.

**Arguments**

| Name            | Type   | Default | Description                                          |
| --------------- | ------ | ------- | ---------------------------------------------------- |
| `connection_id` | string | —       | From `ssh_connect`                                   |
| `command`       | string | —       | Shell command                                        |
| `timeout`       | int    | `30`    | Seconds                                              |

**Returns** `stdout`, `stderr`, `exit_code`.

## `ssh_execute_background`

Run a long-running command without blocking the MCP channel.

**Arguments** — same as `ssh_execute`, returns a `task_id`.

## `ssh_check_background`

Poll a background command. **Arguments**: `task_id`. **Returns** `status`
(`running` / `done` / `error`), accumulated `stdout` / `stderr`, and
`exit_code` once done.

## `ssh_list_background`

No arguments. Returns the list of background tasks across all
connections.

## `ssh_upload` / `ssh_download`

SFTP put / get.

**Arguments**: `connection_id`, `local_path`, `remote_path`.

## `ssh_disconnect`

Close a connection. **Arguments**: `connection_id`.

## `ssh_list_connections`

No arguments. Returns the active connection list.

## `serial_list_ports`

List available serial ports. **No arguments.** **Returns** array of
`{ device, description, hwid, vid, pid, serial_number }`.

## `serial_connect`

Open a serial port by device name.

**Arguments**

| Name            | Type   | Default | Description                                          |
| --------------- | ------ | ------- | ---------------------------------------------------- |
| `port`          | string | —       | `/dev/ttyUSB0` (Linux) / `COM3` (Windows)            |
| `baudrate`      | int    | `115200`| Baud rate                                            |
| `timeout`       | float  | `1.0`   | Read timeout (s)                                     |

Parity/stop-bits/byte-size aren't exposed — the underlying `pyserial`
connection uses its defaults (8N1). `connection_id` is derived as
`"{port}@{baudrate}"`, not separately settable.

## `serial_connect_match`

Open a serial port by matching VID / PID / serial number / description
(instead of guessing `/dev/ttyUSB*`).

**Arguments**

| Name                  | Type   | Default | Description                                   |
| --------------------- | ------ | ------- | ---------------------------------------------- |
| `vid`                 | int    | `null`  | USB vendor ID (e.g. `0x10c4` or `4292`)        |
| `pid`                 | int    | `null`  | USB product ID (e.g. `0xea60` or `60000`)      |
| `serial_number`       | string | `null`  | USB serial number (exact match)                |
| `description_contains`| string | `null`  | Substring match on port description            |
| `hwid_contains`       | string | `null`  | Substring match on the HWID string             |
| `port_contains`       | string | `null`  | Substring match on the device path (e.g. `ttyUSB`) |
| `baudrate`            | int    | `115200`| Baud rate                                      |
| `timeout`             | float  | `1.0`   | Read timeout (s)                               |

At least one match field is required. If more than one port matches,
the call fails and lists the matches so you can narrow the filter.

## `serial_esp32_connect`

ESP32-aware connect that toggles BOOT and RESET via DTR/RTS for
flash-friendly entry, then optionally waits for a boot-ready pattern.

**Arguments**: `port`, `baudrate` (default `115200`), `reset`
(default `true`), `wait_for_boot` (default `true`), `boot_timeout`
(default `5.0`), `ready_pattern`.

## `serial_send`

Send text data. **Arguments**: `connection_id`, `data`, `raw` (default
`false` — appends a line ending unless set), `line_ending` (`"lf"` /
`"cr"` / `"crlf"` / `"none"`, default `"lf"`), `read_response` (default
`true`), `read_timeout` (default `2.0`).

## `serial_send_bytes`

Send raw binary bytes — no UTF-8 encoding, no line ending appended.
For binary protocols like Nordic DTM (2-byte frames) or HCI, whose
frames aren't valid UTF-8.

**Arguments**: `connection_id`, `data` (hex string, e.g. `"0204"`;
whitespace and `0x` prefixes are stripped), `read_response` (default
`true`), `read_size` (bytes to read back, default `2`; `0` means "read
whatever arrives within `read_timeout`"), `read_timeout` (default
`1.0`).

**Returns** `tx_hex`/`tx_len` and, if `read_response`, `rx_hex`/`rx_len`.

## `serial_read`

Read available data. **Arguments**: `connection_id`, `timeout`
(default `2.0`), `bytes` (max bytes to read, default `4096`).

## `serial_read_bytes`

Read raw binary bytes back as hex — no UTF-8 decoding.

**Arguments**: `connection_id`, `size` (default `2`; `0` means "read
whatever arrives within `timeout`"), `timeout` (default `1.0`).

## `serial_wait_for`

Wait until a pattern appears in the stream. The pattern is matched as
a literal substring, not a regex. **Arguments**: `connection_id`,
`pattern`, `timeout` (default `30.0`).

## `serial_expect`

Run a sequence of wait/send steps — each step is
`{ wait_for, send, raw, line_ending, timeout }` (all but one of
`wait_for`/`send` are optional per step).

```json
{
  "connection_id": "uart-1",
  "steps": [
    { "wait_for": "login:",    "send": "root\n" },
    { "wait_for": "Password:", "send": "summit\n" },
    { "wait_for": "[#$] ",     "send": "uname -a\n" }
  ],
  "default_timeout": 10
}
```

Additional top-level arguments: `flush_input` (default `false`),
`default_timeout` (default `30.0`), `default_line_ending` (default
`"lf"`, used for `send` when a step's own `raw` is `false`).

## `serial_send_break`

Send a break signal. **Arguments**: `connection_id`, `duration`
(seconds, default `0.25`).

## `serial_set_dtr` / `serial_set_rts`

Set the DTR / RTS line state. **Arguments**: `connection_id`,
`state` (`true` / `false`).

## `serial_reset_device`

Pulse DTR/RTS to reset an MCU. **Arguments**: `connection_id`,
`method` — one of `"esp32"`, `"esp32_bootloader"`, `"stm32"`,
`"dtr_pulse"` (default), `"rts_pulse"`.

## `serial_flush`

Flush input / output buffers. **Arguments**: `connection_id`, `input`
(default `true`), `output` (default `true`) — both booleans, not a
combined `direction` field.

## `serial_disconnect` / `serial_list_connections`

Close a connection / list active connections.
